# Find and rank Apple inference opportunities

Start with the actual call path in the checked-out runtime. Locate model loading, tokenization, prompt processing, KV allocation, one-token decode, batching, sampling and device dispatch. For each row write the current implementation, measured cost, available alternative, correctness hazard and a falsifier. Mark it tested, rejected, blocked (specific missing evidence) or inapplicable. Rank by time recoverable at the target shape, confidence and cost. Preserve this inventory even when a cheaper lever wins.

| Area | Evidence to collect | Experiments |
|---|---|---|
| Startup / first turn | Launch→ready→first token, cold vs warm filesystem, compilation, page faults and actual weight reads | Compare cache reuse, model loading strategy, compiled pipeline persistence and eager vs lazy initialization. Pin cache state per arm. |
| C1 decode | Active weight bytes, head and KV reads, achieved GB/s at short and long context, CPU sampler time | Compare native quant kernels/packing, smaller effective bpw, KV dtype or window, on-device sampling, command-buffer submission, host synchronization. Check quality and Metal fallback. |
| Speculation | Draft and verify time per step, emitted length, acceptance by depth, shared KV/peak footprint | Test supported MTP, draft model, n-gram or EAGLE implementations against speculation off. Sweep k for each concurrency/context/content type. Count draft head traffic. Try reduced draft vocab only if verification/sampling remains correct. Trace whether verify takes a costly prefill path. |
| Prefill | Prompt-processing throughput by length, stage times (GEMM, attention, MoE, recurrent), transient peak and decode stall during a long prompt | Compare prefill step or ubatch size, SDPA/flash path, quantized GEMM, layout and prompt batching. Look for unnecessary full-vocab logits, MoE padding cliffs and repeated weight unpacking. Prove cache hits separately. |
| Users, KV and state | Effective per-slot context, allocated vs active KV bytes, recurrent slots, eviction, admission, queue tails | Sweep N, prompt/decode batching and KV capacity, prefix reuse, KV cache quant and speculative state. Count shared/copy-on-write prefixes and recurrent state. Prove N users at length and bound p95 latency. |
| MLX | Version and architecture implementation, Metal trace, lazy eval boundaries, active/peak/cache memory | Try built-in quantized_matmul/SDPA, compiled shape-stable compute, reuse materialized buffers, defer unnecessary host reads. Force mx.eval at timing boundaries. Check generate vs server help separately. |
| GGUF / llama.cpp | Per-tensor GGUF types, shard set, offload/split, backend kernel actually selected, compile options | Compare llama-bench prompt processing and generation with controlled context depth; verify under llama-server. Sweep supported flash attention, K/V cache types, batch/ubatch, slot count and Metal kernel path independently. Verify total vs per-slot context in logs. |
| Metal custom kernels | Stage fraction, GPU family, supported feature sets, dtype/layout and matrix dimensions | Follow [the kernel and ANE playbook](metal-ane.md). Compare optimized built-ins, SIMD-group fallback and gated TensorOps on the actual shape distribution. |
| ANE / partitioning | Compilable graph, target device/OS, eligible ops, fallback, transfer/sync time, memory and power | Compare one eligible partition on CPU, GPU and ANE policies using identical inputs. Include state handoff each token and native GPU baseline. Test prefill and incremental decode separately on target hardware. |
| End-to-end and sustained use | Latency distribution, mixed workloads, thermal drift, swap, package/energy interval | Replay a representative session, cold/warm prefixes and simultaneous prefill/decode. For power-sensitive devices report joules/token at equal quality and throughput, with measurement scope. |

Before writing a kernel, bound the possible gain. If a fraction f of wall time is accelerated by s, end-to-end speedup ≤ 1 / (1 − f + f/s). At 10% of request time a 2× kernel gives at most ~5.3% throughput gain. Record the relevant profile and check the shipping dispatch really takes the changed path. If a fusion saves launches but not time, profile the dominant kernel before trying another fusion.

Historical backend-specific measurements and failed levers are preserved as [field notes](field-notes.md). CUDA/XPU graph flags, Xe fences and Linux memory probes belong to the stacks that produced them. On a Mac, test the equivalent behavior through the installed Apple runtime.
